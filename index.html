Core Features

Everything you need.
Nothing you don't.

Three interlocking systems — on-chain, off-chain, and P2P — that make FuseFlash the fastest payment primitive on the planet.

⚡

Tap-and-Go Payments

NFC tap triggers the validator, which ECDSA-signs the transfer intent. On-chain verification in one call — no approval transactions, no friction.

tapAndGo() · ECDSA · EIP-191
🌐

Go P2P Network

Pure-stdlib TCP peer mesh with cryptographically random NodeIDs, Base58-encoded, pronounceable via NATO phonetic alphabet. No external libs.

Go 1.21 · TCP · SHA-256
🌳

Merkle Whitelist Claims

Off-chain Merkle tree built by the validator. Users submit a proof leaf and claim their FLSH allocation in one gas-efficient transaction.

MerkleProof · keccak256 · OpenZeppelin
🛡️

Replay Protection

Every tap nonce and POS session ID is consumed exactly once. Checks-effects-interactions pattern prevents re-entrancy and double-spend.

usedTapNonces · bytes32 · CEI
🏪

POS Checkout

QR-based point-of-sale flow. Merchant generates a session ID; payer scans and confirms in a single on-chain call with a receipt event for indexers.

posCheckout() · sessionId · Event log
🔗

Block Header Sync

eth/63-inspired header chain: SHA-256 canonical hashing, parent linking, concurrent-safe insert, and a Syncer that requests headers when a peer is ahead.

blocksync · Chain · Syncer
Flow

A tap. A sign. A transfer.

The entire Tap-and-Go flow from NFC hardware event to settled on-chain token transfer in under two seconds.

📱

User taps device

The payer's phone or NFC card initiates a tap event. The mobile app reads the payee's address and desired amount from the merchant terminal's broadcast.

✍️

Validator signs the intent

The app calls POST /tap/sign with {from, to, amount, nonce}. The validator service ECDSA-signs the keccak256 hash and returns the signature in <50ms.

⛓️

On-chain verification

The app submits tapAndGo(from, to, amount, nonce, sig). The contract recovers the signer via ECDSA and confirms it matches the registered tapValidator address.

💸

Tokens transferred

The nonce is marked consumed, tokens move from payer to payee in a single ERC-20 transfer, and a TapAndGo event is emitted for indexers and analytics.

✅

Confirmation

Both parties receive real-time confirmation via the P2P node's event subscription, and the Go blocksync layer propagates the new block header to the network.

Stack

Built with the best tools in the game.

Zero compromises. Every technology chosen because it's the fastest, safest, or most battle-tested option available.

🐹
Go 1.21
P2P node, block sync, Base58 & phonetic encoding. Zero external deps — pure stdlib.
🔷
Solidity 0.8.20
ERC-20 FLSH token with Merkle claims, ECDSA tap-and-go, and POS checkout.
🟡
Node.js + Express
Validator service: Merkle tree management, EIP-191 signing, Ethereum address validation.
🛡️
OpenZeppelin
Battle-hardened ERC-20, Ownable, MerkleProof, ECDSA, and MessageHashUtils.
⚗️
ethers.js v6
Wallet management, keccak256, ABI encoding, and ECDSA signing in the validator.
🔨
Hardhat
Smart contract compile, test, and coverage pipeline with the full toolbox.
🌿
merkletreejs
Merkle tree construction with sorted pairs — compatible with OpenZeppelin's on-chain verifier.
🐧
Alpine Linux
Minimal, secure container base. The entire Go node image fits in <15MB.
